# PCB-V07：布局与交付证据门槛

新板或电气/接口变更关联[HW-01～07](design-workflow.md)的需求ID、关键计算和测试计划；本门槛仍检查布局/最终设计证据，不将待测样机性能填为通过，也不以HW记录替代本条逐器件/逐脚检查。

来源：2026-11-03用户复盘。既有PCB-V04、PCB-L01/L17/L20没有成为逐项验收条件，文档编号门禁和DRC不能检出这类执行遗漏。本条增加执行记录，不改变电路参数。

## 两个阶段

| 阶段 | 进入下一步前的条件 |
|---|---|
| layout，开始大规模布线前 | 机械基线一致；每个器件的焊盘/本体及焊接工具空间已审查（含同网、DNP及模块）；每个电源/稳压/偏置脚已有对应电容或准确资料支持的例外，预留同层供电和回地路径；晶振、差分/射频通道未被挤占；使用PLANE或SIGNAL电源区域时，检查PCB-P10规则几何与回流通道。允许局部试布验证可行性 |
| final，完整交付前 | 对最终实际铜路重做装配及逐脚去耦检查；完成同修订网表/连通、GND、转角、线宽/载流、层类型与PCB-P10实际分区几何、晶振/差分、丝印、DRC、泪滴→重铺→DRC和实际制造文件复核 |

不需要每步请求用户批准。未通过或缺证据时自行修正受影响区域；遇到锁定条件或授权冲突才说明冲突。适用项目清单须补充接口专用、隔离、RF等约束，本表不替代准确器件指南。

**PCB-V08 双门槛：** 每次PCB任务分别保留项目规则门禁与当前修订EDA DRC证据；最终交付两者都须通过。布局阶段先完成规则/回路审查，未布线飞线不冒充最终零错误。记录门禁脚本/规则版本、DRC 工具版本、PCB 修订、执行时间和报告路径。门禁通过不证明几何正确，DRC 零错误不证明规则清单已执行，也不替代 PCB-V07 的装配和逐电源脚检查。

## PCB-V09：六类工程审查记录

| 类别 | checks键 | 按项目适用性保留的证据 |
|---|---|---|
| 电气连接 | NETLIST、CONNECTIVITY、DRC | 同修订原理图/PCB逐脚一致、未连接项、当前规则配置及EDA报告；原理图ERC另行记录 |
| 电源完整性 | PI | 正向/返回压降与瓶颈、逐脚去耦/稳定性及实际参考铜路；动态目标与待测项 |
| 信号完整性 | SI | 边沿/传播、真实叠层阻抗、端接/拓扑、偏斜、过孔和测试负载 |
| EMC风险 | EMC | 热回路、SW、时钟、保护泄放、接口返回、耦合/受扰对象；实测/认证状态另列 |
| 热 | THERMAL | 功耗/工况、散热铜/过孔/焊接及邻件影响、估算/温升计划或实测 |
| 制造与装配 | FAB | 板厂/装配厂能力版本、封装/孔/阻焊/钢网/盘中孔工艺、实际Gerber/钻孔/装配与探测空间 |

每类记录当前修订、对象、方法/条件、验收值、结果/裕量、证据及未关闭项。pass仅表示声明范围内已实际完成的设计审查/计算等，不等于样机性能或合规通过；样机待测项显式保留。风险较低的板无需全量仿真，但不能把需要而未做的验证写成not_applicable。确无适用对象时以核验依据标记不适用。

检查器在layout及final均要求RULE_GATE和PCB-P09/P10/P11记录；最终额外要求PI/SI/EMC/THERMAL及已有电气/FAB项。RULE_GATE和DRC必须pass，不能标不适用；未布线布局阶段不强求零未连接DRC，最终交付必须有当前版完整DRC。旧阶段记录缺新项时会被拒绝：应重审适用对象补证据，不批量填pass或仅刷新哈希；历史报告保留其原有范围。

## 最小记录

复制[阶段记录模板](../assets/PCB_STAGE_REVIEW.json)，每阶段各存一份，填project/revision及stage。证据文件复用现有报告和局部图，不重新复制全文。

1. 从本轮原理图/PCB生成inventory.json：`{"components":["U1","C1"],"power_pins":["U1.4"]}`。器件清单包括机械和DNP对象（逐项说明装配状态），电源脚按准确芯片逐脚分类，含VIN/VOUT、模拟域、内部稳压/偏置及有意不用的电源脚。INVENTORY证据记录导出来源、分类方法及覆盖比较；脚名识别不能只靠网络名。无电源脚的无源板填no_power_pins_reason。不凭手写少量清单宣称全覆盖。
2. artifacts登记当前PCB源、inventory及已有核验文件的相对路径和SHA-256。每个checks条目及每个components/power_pins条目填status（pass或not_applicable）、evidence（artifacts中的核验文件键）、rationale（结论/适用边界）；不适用也要有核验依据。布局只要求布局阶段条目，最终要求全部条目。PCB-P09/P10在两个阶段都要检查；对原生 PLANE 或 SIGNAL 电源铜区分别记录物理层、EDA 类型、区域网络/形状/边界、净距、最小铜宽、回流与填充证据。无此类对象时用证据说明不适用。PCB-V08 的规则门禁与当前版 DRC 分开留证。
3. 每个器件的证据注明相邻对象/最小实际间距、本体或庭院/工具接近方向、紧凑例外。不能仅用异网DRC或全板最小焊盘间距证明所有器件可焊；不得为了间距拉长敏感回路。
   按[PCB-V04](layout-manufacturing.md)另查独立同网焊盘重叠/边缘相接、连接铜线和逐对间隙；final的PCB-V02记录Arial/实际字形、适配字号/笔画、开窗/孔口避让和同面走线投影上的必要文字例外。以当前实际制造输出复核，不把截图或DRC视为全部通过。
4. 每个电源脚的证据注明电容位号/容量/电源域及资料页码；关键MLCC按PCB-L22补充准确MPN、工作条件、有效电容/ESR依据及待确认项，不以封装经验上限或标称值代替。layout记录计划的供电及回地，final记录实际焊盘到脚的铜路径、层/过孔和电容GND→有效地铜/过孔→IC地的完整路径。回地测不到时保留未检查，不能仅用最近GND过孔中心距替代完整回流核验。允许多脚共享电容，但每脚仍需有据；区分去耦、储能、晶振负载、VMID及RF匹配。
5. 从实时EDA新导出PCB源后运行：

```powershell
python scripts/check_pcb_stage.py <项目目录>/review/PCB_STAGE_FINAL.json --pcb <当前导出的PCB源.epcb> --stage final
```

布局阶段使用 `--stage layout`；交付阶段必须使用 `--stage final`，不能拿布局记录代替。门禁检查阶段条目、全器件/电源脚覆盖、证据文件存在及哈希、PCB路径/版本一致性。缺项、失败、无依据的不适用或文件变化均返回非零。输入来自人工/工具审查，脚本不判断报告内容是否正确、不自动运行DRC、不证明清单分类完整或硬件性能；阶段通过不能据此放行量产。

改动器件位置/层、封装、供电或地铜后，重审受影响对象并更新对应证据；未受影响记录可在有差异比较的条件下沿用，说明复用依据。最终门禁必须对应新导出的完整设计，不能只刷新哈希伪装完成复核，不能接受历史快照代替当前EDA。
